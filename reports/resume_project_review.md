# 淘宝用户行为分析项目简历投递评审与改进建议

> 备注：本文档保留最初的数据专家评审意见，方便后续继续整改。当前项目已经完成其中的多项高优先级修复，包括北京时间口径、严格用户-商品顺序漏斗、数据质量报告、图表输出、业务洞察改写和 Excel 看板产物。

## 结论

当前项目已经具备数据分析简历项目的基础骨架：有真实公开数据来源、Python 清洗、Pandas 指标分析、SQL 查询、业务洞察报告和看板设计说明。作为数据分析、数据运营、产品运营实习岗位的作品集项目，可以使用。

但如果希望它在简历筛选和面试追问中更有说服力，还需要从“能跑出指标”升级到“口径严谨、业务解释清楚、可视化产物完整、结果可复现”。目前最需要优先改进的是：真实看板产物缺失、时间字段时区口径不明确、转化漏斗定义偏宽、样本抽取方式可能有偏差，以及 README/简历表达存在一定夸大风险。

### 2. 明确并修正时间字段的时区口径

当前清洗脚本直接使用：

```python
pd.to_datetime(df["timestamp"], unit="s", errors="coerce")
```

这会得到未明确时区的时间。由于淘宝业务分析通常应按中国时间理解，建议转换为北京时间。

当前报告中的“购买高峰 05:00”如果按北京时间处理，会变成 13:00。两者的业务解释完全不同：

- 05:00 作为购买高峰不太符合常规消费场景。
- 13:00 作为购买高峰更容易解释为午间活跃或促销触达。

建议修改为：

```python
df["behavior_time"] = (
    pd.to_datetime(df["timestamp"], unit="s", utc=True)
    .dt.tz_convert("Asia/Shanghai")
    .dt.tz_localize(None)
)
```

修改后需要重新生成：

- `data/cleaned_user_behavior.csv`
- `reports/analysis_summary.md`
- `reports/business_insights.md`
- README 中所有涉及日期、小时、峰值时间的结论

### 3. 转化漏斗口径需要更严谨

当前转化率主要是用户级行为共现口径，即只判断同一用户是否出现过浏览、加购、购买行为，没有判断：

- 是否是同一商品。
- 是否按时间顺序发生。
- 是否购买发生在浏览或加购之后。

因此“浏览到购买用户转化率 68.27%”更准确地说是“发生过浏览行为的用户中，有购买行为的用户占比”，不能严格等同于真实漏斗转化。

建议增加三套口径：

| 口径 | 定义 | 适用场景 |
| --- | --- | --- |
| 用户级转化 | 用户是否出现过 pv/cart/buy 行为 | 总体用户行为理解 |
| 商品级转化 | 同一 `user_id + item_id` 是否从 pv/cart 到 buy | 商品行为路径分析 |
| 顺序漏斗转化 | buy 是否发生在 pv/cart 之后 | 更接近真实转化漏斗 |

建议在报告中明确写成：

- 用户级浏览-购买转化率
- 用户-商品级加购-购买转化率
- 按时间顺序的行为路径转化率

这样面试中被追问时会更稳。

## 二、数据可信度问题

### 4. 样本抽取方式可能存在偏差

当前 `prepare_real_data_sample.py` 使用 `head(rows)` 获取前 100,000 行。这个方法虽然简单，但如果原始数据按用户、时间或其他字段排序，前 100,000 行可能无法代表整体数据。

建议：

- 增加 `--seed` 参数。
- 支持随机抽样。
- README 中说明样本抽取方式。
- 如果机器性能允许，扩大到 500,000 或 1,000,000 行样本。

更推荐的表达：

> 从公开淘宝 UserBehavior 数据集中使用固定随机种子抽取 100,000 条行为记录，保证样本可复现。

### 5. 数据质量报告不够完整

当前报告只说明了 raw rows、clean rows、removed rows。作为数据分析项目，建议补充数据质量检查表。

建议增加指标：

- 原始行数
- 重复行数量
- 缺失值数量
- 非法行为类型数量
- 异常时间数量
- 清洗前后日期范围
- 清洗前后行为类型分布
- 清洗后唯一用户数、商品数、品类数

建议新增文件：

- `reports/data_quality_report.md`

这样项目会更像真实工作流程，而不只是计算业务指标。

## 三、分析深度问题

### 6. 业务洞察偏描述型

当前 `business_insights.md` 中的内容主要是“发现了什么”，但还可以补充“为什么重要”和“建议怎么做”。

建议每条洞察采用以下结构：

1. 发现：数据表现是什么。
2. 解释：为什么会这样，业务含义是什么。
3. 行动：可以采取什么运营策略。
4. 验证：后续用什么指标判断策略是否有效。

示例：

> 发现：加购用户购买转化率明显高于普通浏览用户。  
> 解释：加购行为代表更强购买意向，用户已经完成商品筛选。  
> 行动：对加购未购买用户进行优惠券、降价提醒或限时活动触达。  
> 验证：观察触达后购买转化率、购买人数、复购率是否提升。

### 7. 增加用户分层分析

当前已经有高价值用户分析，但还不够体系化。建议增加用户分层。

可增加分层方式：

- 按购买次数：0 次、1 次、2-3 次、4 次及以上。
- 按活跃天数：低活跃、中活跃、高活跃。
- 按行为深度：只浏览、收藏、加购、购买。
- 按复购情况：一次购买用户、复购用户、高频购买用户。

可输出指标：

- 各层用户数
- 各层用户占比
- 各层购买转化率
- 各层复购率
- 各层人均购买次数

简历中可以写：

> 基于用户活跃天数、购买次数和行为深度构建用户分层，识别高价值用户与加购未购买的高潜转化用户。

### 8. 增加品类转化分析

当前项目只列出了购买量最高的 Top 品类。单看购买量容易偏向曝光量大的品类，不能判断品类本身的转化效率。

建议增加品类级漏斗指标：

- 品类 PV 数
- 品类收藏数
- 品类加购数
- 品类购买数
- 品类浏览-购买转化率
- 品类加购-购买转化率
- 品类购买用户数

这样可以区分：

- 高流量高购买品类
- 高流量低转化品类
- 低流量高转化品类
- 低流量低转化品类

这类分析更接近真实电商运营决策。

### 9. 增加留存或复购深挖

当前有复购率，但还可以继续做：

- 首次购买日期 cohort。
- 不同 cohort 的后续购买情况。
- 复购用户与非复购用户的行为差异。
- 复购用户是否更常收藏或加购。

如果时间有限，可以先补一张“购买次数分布表”，性价比最高。

## 七、整体评价

这个项目不是不能投，而是还差一轮“简历项目化包装”。现在它证明了你能使用 Python、Pandas 和 SQL 完成基础电商行为分析；但要让它更像一个有竞争力的简历项目，还需要证明你能：

- 定义严谨的数据口径。
- 处理真实数据中的时间、异常、样本偏差问题。
- 把指标转成业务判断。
- 输出可视化和分析报告。
- 让别人能复现你的分析流程。

建议优先补看板截图、时区处理和严格漏斗口径。这三项完成后，项目质量会明显上一个台阶。
