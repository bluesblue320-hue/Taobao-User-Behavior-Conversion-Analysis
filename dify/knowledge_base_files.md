# Dify Knowledge 建议上传文件

下面这些文件适合作为 Dify Knowledge 的知识库来源。建议优先上传 Markdown 文件，因为它们结构清晰，便于 Dify 按标题、段落和表格进行检索。

| 建议上传文件 | 上传作用 |
| --- | --- |
| `README.md` | 用于回答项目概览、数据集说明、核心指标、运行方法、项目亮点、业务洞察和简历写法等问题。 |
| `reports/analysis_summary.md` | 用于回答核心指标、行为分布、用户级漏斗、用户-商品级顺序漏斗、品类转化、用户分层和高峰表现等分析结果。 |
| `reports/business_insights.md` | 用于回答业务洞察、运营建议、加购未购买用户、复购用户、高价值用户和验证指标相关问题。 |
| `reports/data_quality_report.md` | 用于回答数据清洗逻辑、清洗前后行数、异常时间过滤、字段处理和数据质量检查相关问题。 |
| `dashboard/dashboard_design.md` | 用于回答 Excel 看板结构、KPI 展示、图表布局、仪表盘设计思路和面试展示顺序。 |
| `sql/README.md` | 用于回答 SQL 分析如何复现、SQL 文件结构、使用 PostgreSQL 的原因和查询覆盖范围。 |
| `PROJECT_SHARING_GUIDE.md` | 用于回答如何向 HR、技术面试官或业务面试官介绍项目，以及如何包装 GitHub 作品集展示。 |

## 上传建议

- 上传前先确认文档内容已经与当前 README 和报告保持一致。
- 如果 Dify 支持引用来源，建议开启 citation / attribution，方便面试时解释答案依据。
- 不建议上传完整原始数据文件，例如 `data/UserBehavior.csv`；本项目中提交的样本 CSV 已经足够支撑说明，不适合把大体量原始数据作为问答知识库。
- 如果后续新增真实 Dify 应用截图、Web App 链接或演示页面，可以再补充对应说明文档，但不要提前写入不存在的链接。
